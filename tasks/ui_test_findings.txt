===== PERF (./ui_test perf, screenshots in build/ui_test_logs/perf, GPU label = avg of 20 frames) =====
2026-11-11, M2, 2400x1440 framebuffer, vsync 60 fps in every case:
    empty scene 2.05 ms | picker clip on 3.42 / off 3.44 | lab clip on 4.41 / off 4.39 (55 draw calls)
    10 full-window layers: no clip 11.96, 3 nested clips each 14.67, opaque 11.94 | 20 layers 14.68
Reading:
- Clipping is not the cost in the real scenes (on vs off within 0.02 ms). Worst synthetic case (every
  pixel of 10 full-window layers tested against 3 clip parents) adds ~2.7 ms.
- The GPU number does not scale with work: 10 extra full-window layers add ~10 ms over empty, the next
  10 only ~2.7 ms; blending vs opaque is the same. Apple GPUs lower their clock when a frame is easy and
  the timestamps measure wall time at that clock, so at 60 fps vsync the label mostly shows how much of
  the frame budget the GPU chose to use, not the real cost. Compare with Xcode GPU capture / Metal HUD,
  or measure with vsync off, before optimising for it.
- Full clock (load until fps drops, 2026-11-11): 40 layers 14.94 ms / 60 fps, 80 layers 26.04 ms / 38 fps,
  160 layers 51.49 ms / 19 fps -> ~0.32 ms per full-window translucent layer (~11 Gpix/s, fine for M2).
  80 layers under 3 clip parents: 73.05 ms / 13.7 fps -> ~0.91 ms per layer: 3 clip tests make every pixel
  ~2.8x more expensive (~0.2 ms per clip test per full window). Clipping is cheap only because the test
  scenes are small; per pixel it is the most expensive part of the rect shader.
  Why: per fragment per clip the shader calls rotate() (radians + sin + cos) for the world position and for
  each clip, divides by scale and reads the clip struct from the SSBO.
  Ideas: (1) on the CPU, do not upload a clip ancestor when the node's rect is fully inside it (most
  children are; you already test "fully outside" in is_clipped_by), so number_clipping is 0 for them;
  (2) upload each clip as a precomputed world->clip-local 2x3 matrix (no sin/cos per pixel);
  (3) compute the world position in the vertex shader and pass it as a varying.
- After CPU clip culling (02237c1, 2026-11-11): 80 layers under 3 clip parents 26.04 ms / 38 fps, same as
  80 layers without clips (26.04 ms / 38 fps). Before: 73.05 ms / 13.7 fps. Fully-inside nodes upload 0 clips.
