UI API NEEDS (Engine:: layer)
Collected while building the UI test scenes (modal, colour picker, component lab) and the drive / fuzz
harness. Every item is something the tests or the scenes had to work around by reading components,
using engine globals, or doing by hand what an app will need again and again.
Format: why it is needed -> what the API could look like (names are suggestions, your call).
Mark with [Done] when added; the tests will be switched over to the public API after that.

===== P1: NEEDED FOR SMOOTH APP CODE =====
[Handled]: 1. Click / tap event instead of raw touch states.
    Why: every button in the kit re-implements "BEGAN -> darken, ENDED -> restore, fire only if the finger
    moved less than 12 px, ignore CANCEL". Rows, swatches, recent items all repeat it.
    API: set_click_caller(e, std::function<void(Handle)>) - fires on ENDED inside the node when the touch
         was not claimed by a scroll layout and moved less than a click slop (engine constant, settable).
         Optional: set_pressed_caller(e, fn(Handle, bool pressed)) for the pressed look.

[Hanled]: 2. Safe callbacks when a node is destroyed inside its own callback.
    Why: "Destroy self" cleans up the dialog from inside its button's touch callback; the kit wraps every
    caller in try/catch so a stale handle logs instead of crashing.
    API: clean_up called during touch dispatch is deferred to the end of the dispatch (or the engine
         checks is_valid(e) before each remaining caller in that frame). Then no try/catch is needed.

[Handled]: 3. Scroll offset get / set.
    Why: tests read Scroll_Information.container_handle and call get_position on the inner container to
    know how far a list is scrolled; an app needs "scroll to top", "scroll to item", "keep position".
    API: get_scroll_offset(e) / set_scroll_offset(e, vec2) (clamped to the content),
         scroll_to_child(e, child), get_scroll_max_offset(e).
         Optional: set_scroll_caller(e, fn(Handle, vec2 offset)) to react to scrolling (e.g. load more).

[Handled]: 4. World-space queries.
    Why: the drive computes world centres by hand (position + rotate((0.5 - anchor) * size * scale)) from
    World_Transform_2D + Size to click a node; tooltips, popups and drag & drop need the same.
    API: get_world_position(e), get_world_rect(e) (4 corners or AABB), is_world_visible(e),
         convert_to_node_space(e, world_point) / convert_to_world_space(e, local_point).

[Handled/Claude support logic]: 5. Label alignment, max width and wrapping.
    Why: Font_2D already has align, but Engine:: has no setter. Multi-line body text in the dialog is
    centred line by line with no way to left-align; long labels overflow buttons instead of wrapping.
    API: set_label_align(e, LEFT | CENTER | RIGHT), set_label_max_width(e, w) -> word wrap,
         optional set_label_overflow(e, CLIP | ELLIPSIS).

[Handled]: 6. Simple layout containers (row / column / grid).
    Why: the picker places 72 swatches, 3 sliders and the recent row by hand (x = 8 + step * i) and
    recomputes the inner container size every time an item is added; the lab boxes do the same.
    API: set_layout_kind(e, NONE | ROW | COLUMN | GRID) + set_layout_spacing(e, gap),
         set_layout_padding(e, insets), set_layout_columns(e, n). Children are positioned in the
         relative-size pass; a scroll layout's inner container grows to fit (auto content size).

[Handled]: 7. Find nodes by name / tag.
    Why: the drive finds buttons by scanning every Label_Renderer_Information for a text prefix and the
    measure label by walking box_5's grandchildren; apps need the same to wire UI loaded from data.
    API: set_name(e, string) / get_name(e), find_child_by_name(parent, name, recursive = true).

===== P2: QUALITY OF LIFE =====
[]: 8. Input injection for tests / tools.
    Why: the drive declares engine internals as extern (spawn_touch, release_touch, window_unique_touch_id,
    on_scroll_fire, on_cursor_*) to fake clicks, drags and the wheel.
    API: Engine::Input::touch_down(world), touch_move(world), touch_up(world), scroll(world, delta)
         - same path as GLFW callbacks, usable by tests, replays and automation.

[]: 9. Handle from id / tree validity.
    Why: tests rebuild a Handle from an id through entity_generator.generations and read
    Tree_Information.valid_child to know if a node is attached to the root.
    API: is_in_tree(e) (attached to the root), and keep registry ids internal so ids never leak out.

[]: 10. Hover and touch cancel info.
    Why: desktop buttons usually react to hover; on cancel (scroll claimed the touch) the kit only knows
    the state name.
    API: set_hover_caller(e, fn(Handle, bool inside)) using the cursor position the engine already tracks.

[]: 11. Scroll layout options.
    Why: the drag threshold (7.5 px) is hard-coded; bounce / fling are TODOs in the touch container.
    API: set_scroll_drag_threshold(e, px), set_scroll_bounce_enabled(e, bool),
         set_scroll_inertia_enabled(e, bool).

[Done]: 12. Image fill mode.
    Why: with use_custom_size an image stretches to its rect; avatars / thumbnails need aspect kept.
    API: set_image_fill_mode(e, STRETCH | FIT | FILL) (FILL crops via image_rect).

[Handled]: 13. Font size limits made visible.
    Why: font sizes are clamped to [6, 72] silently and the stroke is capped by the SDF padding.
    API: get_label_min_font_size / get_label_max_font_size (or a log once when clamped).

===== EDITOR (scene editor app in editor/, target `editor`, added 2026-11-11) =====
Order = how much the editor needs it. The editor builds and runs today with stand-ins in
editor/editor_api.cpp; when an item lands, the stand-in becomes a one-line forward.

[Done]: 17. Image size before the frame runs.
    Why: thumbnails must fit their cell keeping aspect, and a dropped image is created at its pixel size
    (scaled down only if bigger than the canvas). get_content_size / get_inner_renderer_size are 0 until the
    renderer pass has run for that node.
    API: glm::vec2 get_texture_size(const std::string& image_path) - loads the texture if needed,
         {0, 0} when the file is missing.
    Stand-in: Vulkan::load_texture + Vulkan::view_texture (reaches into the Vulkan layer).

[Done]: 18. Claim a touch (drag out of a scroll layout).
    Why: dragging a resource cell out of the resource grid: after 7.5 px the scroll layout starts scrolling
    too, so the drag and the scroll fight.
    API: void claim_touch(const Handle& e) - called from e's touch callback: e keeps this touch, every other
         listener of the same touch (the scroll layout) gets TOUCH_CANCEL once and nothing more.
    Stand-in: the resource panel has touch scrolling off (mouse wheel only).

[Done]: 19. Topmost node at a point (no touch listener needed).
    Why: picking what is under the cursor: selecting nodes on the canvas, choosing a drop target (drop onto
    a layout = make it the parent), later hover. find_entites_listen_touch_at only returns listeners.
    API: Handle find_topmost_node_at(const glm::vec2& world, const Handle& under = root) - same rules as touch
         (visible, not clipped, topmost by draw order), invalid handle when nothing.
         Optional filter: std::function<bool(Handle)> to skip e.g. the selection frame.
    Stand-in: every canvas node gets its own touch listener; drop target = canvas only (point in world rect).

[Done]: 20. Cursor world position at any time.
    Why: GLFW's file-drop callback has no position; files dropped from Finder are placed under the cursor.
    The engine already tracks it in its cursor callback (engine.cpp ~629).
    API: glm::vec2 get_cursor_world_position().
    Stand-in: glfwGetCursorPos + y flip with get_window_size.

[Done]: 21. Fast-move touch cancel off for mouse input.
    Why: touch_handler.cpp:104 cancels the touch when the mouse moves more than half the window in one frame
    or leaves the window: a quick drag across a big window is cancelled halfway.
    API: set_touch_cancel_on_fast_move(bool) (global), or skip that rule for the mouse.

[Done]: 22. Mouse button + modifier keys in touch events.
    Why: right-click menu, Shift+click multi-select, Alt+drag duplicate. Only the left button is handled and
    mods are dropped.
    API: an extra touch info: button (LEFT / RIGHT / MIDDLE) and mods, e.g.
         get_touch_button(touch) / get_touch_mods() or a richer caller signature.

[Done]: 24. BUG set_touch_layout_scroll_enabled(e, false) does not stop drag scrolling.
    engine.cpp ~1903 switches Touching_Information on scroll_info.container_handle (the INNER container); the
    listener that scrolls is container_touch_handle (SCROLL_LISTENER_CONTAINER). So the layout still takes the
    touch after 7.5 px and cancels the child's drag. Fix: use container_touch_handle (setter and getter).
    Editor stand-in: Editor_Api::set_scroll_drag_enabled switches the listener child off directly.

[Done]: 25. BUG to_my_position_space(e, world) is measured from e's anchor point, not from e's bottom-left.
    Children are positioned from the parent's bottom-left, so converting a world point to "where a child must be
    placed" is off by anchor * size: with anchor (0.5, 0.5) the parent's centre maps to (0, 0) = its corner.
    (repro-api item 4 only checked anchor (0, 0) nodes, so it passed.) Fix: + anchor * content_size at the end
    (same for any inverse helper). Editor stand-in: Editor_Api::to_child_space.

[Handled]: 26. Shaders (res/shader/...) are loaded relative to the working directory, images/fonts relative to
    Utils::get_root_path(). Started from another folder (Finder double-click: cwd = home) the app aborts:
    "fail to load file: res/shader/draw_texture_2D/vert_shader.vert.spv does not exist!".
    Fix: prefix shader paths with Utils::get_root_path() like images. Editor stand-in: editor_main.cpp sets
    the working directory to the executable's folder at startup.

[Done]: 27. Clear colour setter (GPU).
    Why: the render pass clears to grey 0.5 (vk_core.cpp ~523) and nothing can change it, so an app that wants
    a dark background draws a full-window rect: ~0.45 ms GPU per full window at 2880x1640 (full clock), for
    pixels the clear already writes for free. The editor now uses 4 margin strips instead (0.64 ms vs 1.12 ms).
    API: void set_clear_color(const glm::vec3& color) (Engine:: forwarding to Vulkan).

[]: 28. Cheaper opaque rects (GPU, engine side).
    Why: every layout runs the rounded-rect SDF + border + clip shader with blending on every pixel, even a
    plain opaque rectangle (radius 0, no border, opacity 1, no partial clip) which is most of the UI area.
    Ideas, cheapest first: (a) shader early-out when radius == 0 && border == 0 (skip the SDF); (b) a pipeline
    with blending off for fully opaque draws; (c) opaque-first with depth (draw_index as depth) so pixels hidden
    under a panel are never shaded. Measure with ./editor --perf (editor cost = load80_editor - load80).

[]: 23. Later for the editor: save / load a scene file (node tree + properties), get_children order /
    reparent keeping world position, text field for rename (= item 15), hover cursor (deferred with select
    mode).

===== EDIT BOX + PROGRESS BAR (spec 2026-11-11) =====
Order inside 29 = build order; 29a-29d are the core (a usable single-line edit box), 29e-29h come after.
Names are suggestions. Coordinates as everywhere: world y up, label-local x from the label's left edge.

[]: 29. Edit box (single-line first).
  29a. Engine owns keyboard input.
    Why: today the app sets glfwSetKeyCallback itself (main.cpp, tests, editor), so the engine cannot route
    keys to a focused node. GLFW allows one callback per window.
    API: in Engine::init register glfwSetKeyCallback + glfwSetCharCallback, and forward everything not
         consumed by a focused edit box to the app:
         void set_key_caller(std::function<void(int key, int action, int mods)>)   // app shortcuts
         Char input: UTF-32 code points from the char callback (GLFW already composes dead keys / Telex on
         macOS); store text as UTF-8.
    Note: the font atlas covers START_CHAR..NUM_CHAR (ASCII). Non-ASCII code points draw '*' today
         (Font::to_char_index). Fine for v1; Vietnamese needs a bigger atlas later (29h).

  29b. Keyboard focus.
    API: void set_focus(const Handle& e)         // invalid handle = no focus
         Handle get_focus()
         bool is_focusable(e) / set_focusable(e, bool)   (edit boxes are focusable by default)
         set_focus_caller(e, fn(Handle, bool focused))   // e.g. border colour on focus
    Rules: TOUCH_BEGAN on a focusable node focuses it; BEGAN anywhere else clears focus (before dispatch,
         so a button click still blurs the edit box). clean_up / set_visible(false) of the focused node or an
         ancestor clears focus. Tab / Shift+Tab: next / previous focusable in draw order (later).

  29c. Edit box node.
    API: Handle create_edit_box()            // layout (background, border, clip on) + inner label + caret
         void set_edit_box_text(e, const std::string& utf8) / std::string get_edit_box_text(e)
         void set_edit_box_placeholder(e, text, color)      // shown when empty and not focused
         void set_edit_box_max_length(e, int code_points)   // 0 = unlimited
         void set_edit_box_font(e, path, size), set_edit_box_text_color(e, color), set_edit_box_padding(e, px)
         set_edit_box_changed_caller(e, fn(Handle, const std::string&))   // every edit
         set_edit_box_submit_caller(e, fn(Handle, const std::string&))    // Enter
         (Esc: blur without submit.)
    Keys while focused: printable chars insert at the caret; Backspace / Delete; Left / Right;
         Home / End (and Cmd+Left / Cmd+Right on macOS); Enter = submit; Esc = blur.
    Key repeat: handle GLFW_REPEAT like PRESS for Backspace / Delete / arrows.

  29d. Caret placement and drawing.
    Why: clicking inside the text must put the caret between the right characters; the caret must be drawn
         at that x. Per-char x already exists in Draw_Font_2D::get_char_position_at.
    API (also useful for labels in general):
         float get_label_char_x(const Handle& label, int index)       // x of the gap before char `index`,
                                                                      // index == length -> end of text
         int   get_label_char_index_at(const Handle& label, float local_x)  // nearest gap
    Caret: a 2 px layout child, height = line height, blinking 0.5 s on / 0.5 s off, solid while typing
         (reset the blink on every edit). Needs a per-frame tick inside process_frame (dt is there).
    Scrolling: when the text is wider than the box, offset the inner label so the caret stays inside the
         padding (clip is already on the box).

  29e. Selection: Shift+arrows, drag to select, double-click = word, Cmd/Ctrl+A = all; selection drawn as a
       rect behind the text; typing replaces the selection.
  29f. Clipboard: Cmd/Ctrl+C / X / V via glfwGetClipboardString / glfwSetClipboardString (strip newlines in
       single-line mode).
  29g. Modes: password (draw '*' per code point, copy disabled), numeric only, read-only, multi-line (Enter =
       newline, Up / Down move by line; reuses the label wrap code).
  29h. Unicode: atlas beyond ASCII (Vietnamese at least: Latin Extended + combining marks), UTF-8 aware
       label layout (today one char = one byte). IME candidate window (CJK) is a separate, larger task.

  Tests I will add when 29a-d land (editor self-test + ui_test repro): focus by click / blur by click outside,
  type "hello" via the char path, Backspace, Left x2 + insert, Home / End, Enter fires submit once, Esc blurs,
  max length, caret x == get_label_char_x(index) after each step, clean_up while focused clears focus.
  First use in the editor: rename the selected node in the inspector.

[]: 30. Progress bar (optional engine widget; can be built today).
    Today: track = layout (background, radius, clip on), fill = child layout with set_size_percent({value, 1})
           and the same radius; set_progress = one setter, resizing the track keeps the fill correct.
    If it becomes an engine widget: create_progress_bar(), set_progress(e, 0..1), get_progress(e),
         set_progress_direction(e, LEFT_TO_RIGHT | RIGHT_TO_LEFT | BOTTOM_TO_TOP), set_progress_colors(e,
         track, fill). Optional later: animate to value (needs actions, item 14), 9-slice images for track/fill.
    I will add it to the editor UI kit (helper on top of layouts) unless you prefer the engine widget.

===== SCENE FILE (spec 2026-11-11) =====
[]: 31. Save / load a scene (Cocos Studio .csd / Godot .tscn equivalent).
    Why: the editor must save what you build and the game must load it at runtime, so load / save live in the
    engine (editor and game share it); game code then finds nodes with find_node_by_name / find_node_by_tag.

  31a. API.
    bool   save_scene(const Handle& root_of_scene, const std::string& path);   // the node + its subtree
    Handle load_scene(const std::string& path, const Handle& parent = root);  // invalid handle on failure
    Optional: std::string scene_to_string(e) / Handle scene_from_string(json, parent) (tests, copy & paste,
    undo snapshots, prefabs = load the same file many times).
    Paths inside the file are relative to Utils::get_root_path() ("res/..."), like set_image_path.

  31b. Node type (missing today: Description is internal).
    API: NODE_TYPE get_node_type(e)  -> NODE / LAYOUT / IMAGE / LABEL / SCROLL_LAYOUT (public enum).
    Scroll layout internals (inner container, touch container) are never saved; their children are saved as
    the scroll layout's children (get_scroll_layout_children) and loaded with add_child_to_container.

  31c. Size / position mode (so what loads back equals what was saved).
    Problem: a node can be sized by content size, size percent or pinning, and positioned by position or
    position percent. Saving the resolved numbers would lose "50% of parent" after a reload.
    API: SIZE_MODE get_size_mode(e) -> AUTO (image / label natural size) | CUSTOM | PERCENT | PINNING
         POSITION_MODE get_position_mode(e) -> ABSOLUTE | PERCENT
    (or has_size_percent / has_size_pinning / has_position_percent booleans).
    Save only the active mode's value; load calls the matching setter.

  31d. Getter gaps found by reading engine.h (setter without getter):
    set_label_padding_vertial -> typo; rename to set_label_padding_vertical (getter already has that name).
    set_use_custom_size_enabled -> check: no is_use_custom_size_enabled (image / label versions exist).
    set_touch_caller / set_click_caller -> not saved (code). Touch flags (touch enabled, swallow) are saved.

  31e. File format: JSON (vendor/json.hpp, already used by the glTF parser). One object per node:
    { "version": 1, "root": NODE }
    NODE = {
      "type": "layout|image|label|scroll_layout|node", "name": "...", "tag": 0,
      "position": [x, y] | "position_percent": [x, y],
      "anchor": [x, y], "scale": [x, y], "rotation": deg, "z": 0,
      "opacity": 1, "color": [r, g, b], "visible": true,
      "size": [w, h] | "size_percent": [x, y] | "pinning": {"left":..,"right":..,"top":..,"bottom":..} | (none = auto),
      "touch": {"enabled": false, "swallow": true},
      "layout": {"background": true, "background_color": [..], "radius": 0, "border_width": 0,
                 "border_color": [..], "clipping": false},
      "image":  {"path": "res/..", "rect": [x, y, w, h], "nine_scale": null | {"rect": [..]} | {"ratio": [..]}},
      "label":  {"text": "..", "font": "res/fonts/..", "size": 16, "stroke_size": 0, "stroke_color": [..],
                 "h_align": "left|center|right", "v_align": "top|center|bottom",
                 "padding": [h, v], "fit": "clip|ellipsis"},
      "scroll": {"direction": "vertical|horizontal", "speed": 30, "inner_size": [w, h],
                 "touch_scroll": true, "swallow_scrolling": true},
      "children": [ NODE, ... ]        // in z order; loads keep the saved z values
    }
    Rules: write only keys that differ from the default (small files, easy diffs); unknown keys are ignored
    (old engines can read newer files); "version" lets load migrate older files.

  31f. Errors: a missing image / font loads with the default image / font and logs once (same as today);
    a broken file returns an invalid handle and logs the JSON error position; never a half-built tree.

  Tests I will add when 31 lands: round trip (build the lab / label scenes -> save -> clear -> load -> compare
  every getter of every node, by name path), percent / pinning survive a parent resize after reload, scroll
  layout children come back inside the container, load twice under different parents (prefab), broken file
  -> invalid handle and no leaked nodes (pool check), missing image path -> default image.
  In the editor: File > Save / Open (Cmd+S / Cmd+O), hierarchy panel, inspector with edit boxes (item 29).

===== TRANSFORM GIZMO (spec 2026-11-12) =====
Goal: the selected node gets a box with 8 handles (4 corners + 4 edge middles) + a rotate handle, like
Godot / Cocos Studio. Hover an edge -> resize cursor, drag -> resize; hover outside a corner -> rotate cursor,
drag -> rotate; drag inside -> move (works today). Later the same box gets 3D axis arrows (items 38-41).
Order = build order. 32-34 unblock the 2D gizmo; 35-37 make it nicer.

What the editor does itself (no engine API needed): the box (one layout, background off, border 1 px,
rotated with the node), handle squares and the rotate circle (layouts with radius), the resize math (the
opposite edge stays fixed, Shift = keep aspect, Alt = from the centre), the rotate math (Shift = 15 deg snap),
and one undo step per drag. Resize writes content size for layouts and custom-size images; images and labels
in AUTO size mode write scale (Cocos behaviour). Needs 31c (get_size_mode) to choose.

[]: 32. Cursor move without a button (hover). Starts the deferred hover / select-mode work.
    Why: the resize cursor must change when the mouse is over an edge BEFORE any click. Touch callers only
    fire while a button is down, so today the editor cannot know where the mouse is between clicks.
    API (minimum): void set_cursor_move_caller(std::function<void(glm::vec2 world)>)   // every cursor move
         The editor hit tests its own handles with that. Item 10 (set_hover_caller per node) can be built on
         the same per-frame hit test later.
    Rules (from the hover design notes): run the hit test once per frame after the transform pass (not
    inside the GLFW callback), use the same visible / clip / topmost rules as touch, call
    enter / exit from a diff of last frame vs this frame, and a caller that destroys nodes must be safe
    (same deferral as item 2). While a button is held, the pressed node keeps the hover (no flicker
    during a drag). Cursor leaving the window = exit for everything (glfwSetCursorEnterCallback).

[]: 33. Cursor shape.
    Why: resize / rotate need the system arrows so the user sees what a drag will do.
    GLFW 3.4+ (you have 3.5.1 on macOS, 3.4 on Windows) has all of them as standard cursors.
    API: enum class CURSOR_SHAPE { ARROW, IBEAM, CROSSHAIR, HAND, RESIZE_EW, RESIZE_NS, RESIZE_NWSE,
                                   RESIZE_NESW, RESIZE_ALL, NOT_ALLOWED };
         void set_cursor_shape(CURSOR_SHAPE shape);        // glfwCreateStandardCursor once, cache, glfwSetCursor
         void set_cursor_image(const std::string& path, glm::ivec2 hotspot);   // custom (rotate arrow)
    Notes: create each GLFWcursor once and destroy them in Engine cleanup. Setting the same shape twice
    does nothing (it is called on every move). On a rotated node the editor picks the diagonal / straight
    arrow closest to the edge direction, so these 4 directions are enough.
    Later: per node set_hover_cursor(e, shape) with item 10, so a button shows HAND by itself.

[]: 34. World rotation / scale (or the world matrix).
    Why: the box must turn with the node, and a drag must be turned back into the node's own axes:
    "drag the right edge 10 px" on a node rotated 30 deg inside a parent rotated 45 deg is 10 px along the
    node's local x. get_world_rect gives 4 corners, so rotation and size can be guessed from them, but a
    negative scale (flip) and a zero-size node make that guess wrong.
    API: float get_world_rotation(const Handle& e);      // degrees, all parents included
         glm::vec2 get_world_scale(const Handle& e);
         or one call: glm::mat3 get_world_transform(const Handle& e) (+ its inverse), which also covers 4.
    Also check: to_my_position_space (item 25) uses the full inverse (rotation + scale), not only position.

[]: 35. Pick filter for find_topmost_node_at (item 19 "optional filter", + finding 39).
    Why: the box and its handles sit on top of the node; clicking the node through the box must still
    select the node, and clicking a handle must not change the selection.
    API: find_topmost_node_at(world, under, std::function<bool(Handle)> skip).
    Stand-in until then: topmost_layout_at (draw-order walk) + the editor checks its handles first.

[]: 36. Overlay layer (gizmo drawn above the scene, not clipped by it).
    Why: the gizmo is a canvas child today so z order fights the scene's z values, and handles at the canvas
    edge are cut by the canvas clip. Handles must also keep their size in pixels when the canvas zooms.
    API (one of): a second root drawn after the main root (Handle get_overlay_root()), or
         set_ignore_parent_clip(e, bool) + a z order range reserved for tools.
    Stand-in: the gizmo stays a canvas child with z = next_z + 1000.

[]: 37. Canvas zoom / pan (later, with 36).
    Why: small sprites need zoom to grab a handle. Scaling the canvas works, but the clip rect and touch
    hit test must use the scaled rect, and the gizmo (36) must not scale with it.
    API: none new if set_scale on a clipping layout clips + hit tests correctly; please confirm, I will add
    a repro check (scaled clip layout: touch outside the visible part must miss).

===== 3D GIZMO (later, listed so the API fits) =====
The axis gizmo: 3 arrows (X red, Y green, Z blue) to move, 3 rings to rotate, 3 small cubes to scale, plus a
view cube / axis widget in the viewport corner that shows the camera direction (click X / Y / Z = snap the
view). For 2D nodes the same gizmo shows only X / Y arrows + the Z ring, so one code path serves both.
Most of these are already in tasks/editor_todo.txt section 1 (draw layer); here is what the gizmo adds.

[]: 38. Camera + projection both ways.
    API: set_camera(position, target, up, fov, near, far), get_view() / get_projection(),
         glm::vec3 screen_to_ray(glm::vec2 screen) (origin + direction),
         glm::vec2 world_to_screen(glm::vec3) (to place 2D labels "X" "Y" "Z" next to the arrow tips).
